# Agent Inbox — Slice 3: Web UI — Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** A phone-usable, server-rendered inbox on the tailnet: a feed, an entry page, live refresh, and a sandboxed HTML frame that cannot submit an answer.

**Architecture:** Slice 2's `serve.run` is the process. This slice starts two `http.server` threads inside it: the UI on port 8797 and the frame on port 8798 (8787 is the chrome bridge and 8788 is the am-videos API). Tailscale publishes them on HTTPS 8444 and 8445; port 443 stays the existing Funnel. The UI accepts only a Tailscale login header of `tjdsneto@`. Tests set `INBOX_ALLOW_INSECURE=1`, which the LaunchAgent must not set. No Telegram and no notifications in this slice.

**Tech Stack:** Python 3.14 stdlib `http.server`, SSE, `tailscale serve`. Postgres stays on `localhost:5433`.

**Spec:** [`../specs/2026-11-23-agent-inbox-design.md`](../specs/2026-11-23-agent-inbox-design.md) section Web UI. Depends on slice 2 ([`2026-11-23-inbox-delivery.md`](2026-11-23-inbox-delivery.md)).

**Work on:** `/Users/tjdsneto/projects/agent-tools` branch `main`. Do not commit unrelated `modules/registry/**` dirt.

## File structure

| File | Responsibility |
|---|---|
| `modules/inbox/src/agent_inbox/web.py` | feed, entry, answer/follow-up/read forms, SSE |
| `modules/inbox/src/agent_inbox/frame.py` | HTML frame on its own origin |

| `modules/inbox/tests/test_web.py` | handler tests over a real test database |

Ports: UI `8797`, frame `8798`. Override with `INBOX_HTTP_PORT` and `INBOX_FRAME_PORT`.

Auth header: `Tailscale-User-Login`. Accept only values that start with `tjdsneto@`. Missing header → 403 with the text `tailnet login required`. `INBOX_ALLOW_INSECURE=1` skips the check.

Dismiss:

- An info entry: `archive`.
- A question in `undelivered`: set `delivery.dismissed` true. The default feed hides those. There is no new state.

Batch actions on the feed are withdraw (open questions) and dismiss (info, or undelivered questions). No batch answer.

`modules/inbox/tests/test_web.py`:

```python
import os
import threading
from http.client import HTTPConnection

import pytest

from agent_inbox import store
from agent_inbox.validate import validate_request
from agent_inbox.web import make_server

CHOICE = {"type": "choice", "options": [{"id": "a", "label": "A"}, {"id": "b", "label": "B"}]}
os.environ["INBOX_ALLOW_INSECURE"] = "1"


@pytest.fixture
def http(conn):
    server = make_server("127.0.0.1", 0)
    thread = threading.Thread(target=server.serve_forever, daemon=True)
    thread.start()
    host, port = server.server_address
    yield host, port
    server.shutdown()


def _get(http, path, headers=None):
    conn = HTTPConnection(http[0], http[1], timeout=5)
    conn.request("GET", path, headers=headers or {})
    resp = conn.getresponse()
    return resp.status, resp.read().decode()


def test_feed_pins_open_questions_above_unread_info(conn, http):
    q = store.create_entry(conn, "ask", validate_request({"title": "Q", "control": CHOICE}, "ask"), engine="claude", session_id="s-1")
    info = store.create_entry(conn, "post", validate_request({"title": "I"}, "post"), script="cron")
    old = store.create_entry(conn, "post", validate_request({"title": "Old"}, "post"), script="cron")
    store.archive(conn, old["id"])
    status, body = _get(http, "/")
    assert status == 200
    assert body.index("Q") < body.index("I")
    assert "Old" not in body
    assert q["id"] in body and info["id"] in body


def test_entry_layers(conn, http):
    e = store.create_entry(
        conn, "ask",
        validate_request({"title": "Which split?", "summary": "because", "html": "<p>diagram</p>", "control": CHOICE}, "ask"),
        engine="claude", session_id="s-1",
    )
    status, body = _get(http, f"/e/{e['id']}")
    assert status == 200
    assert "Which split?" in body and "because" in body
    assert 'sandbox="allow-scripts allow-popups"' in body
    assert "allow-same-origin" not in body and "allow-forms" not in body
    assert f"http://127.0.0.1:8798/h/{e['id']}" in body
    assert "Reference only. Answer below." in body


def test_anonymous_request_is_forbidden(conn, http, monkeypatch):
    monkeypatch.delenv("INBOX_ALLOW_INSECURE", raising=False)
    assert _get(http, "/")[0] == 403
    assert _get(http, "/", {"Tailscale-User-Login": "tjdsneto@example.com"})[0] == 200
    assert _get(http, "/", {"Tailscale-User-Login": "someone@example.com"})[0] == 403
```

`make_server` reads `INBOX_ALLOW_INSECURE` per request, not at import, so the monkeypatch in the third test works. The first two tests run with the env var set.

- [ ] **Step 2: Feed query**

Groups, in order, each ordered by `CASE priority WHEN 'urgent' THEN 0 WHEN 'normal' THEN 1 ELSE 2 END, created_at, id`:

1. `kind = 'ask' AND state = 'open'`
2. `kind = 'post' AND state = 'unread'`
3. everything else that is not `archived`, not `withdrawn`, not `superseded`, and not `delivery->>'dismissed' = 'true'`

Query filters from the query string: `kind` (`ask` → Needs answer, `post` → Info, absent → All), `engine`, `state`. "Needs answer" is `kind=ask&state=open`. A `history=1` parameter swaps the query for `state IN ('delivered','expired','withdrawn','superseded','undelivered','archived')`.

`list_entries` hides `html`, `summary`, and `detail`. The feed uses it. The entry page uses `get_entry`.

- [ ] **Step 3: Pages**

One HTML document, no external CSS or JS files. A `<style>` block: system font, body margin 16px, cards as `article` with 12px padding and a 1px border, tap targets at least 44px. A `<script>`:

```html
<script>
const es = new EventSource("/events");
es.onmessage = () => location.reload();
</script>
```

Feed card: id, title, priority, project basename, state, and the reachability word from `delivery.reachability` when present (`live`, `resumable`, `held`, `unreachable`). Held with `delivery.reachable_at` shows `answerable at ~HH:MM` using the last five characters of that field when it contains `T`, otherwise the raw value. Link the card to `/e/<id>`.

Entry page, in this order:

1. Title and state.
2. Summary as text (escape HTML; do not render summary markdown as HTML).
3. The iframe, only when `html` is non-empty, plus the sentence `Reference only. Answer below.`
4. Detail as escaped text.
5. Source link when `source.url` is present (`target="_blank" rel="noopener"`).
6. The thread: each follow-up and reply as a paragraph.
7. The control form posting to `/e/<id>/answer`, and a follow-up form posting to `/e/<id>/followup`.
8. For an unread or read info entry, opening the page calls `mark_read` before rendering.

Answer form:

- `choice`: radio per option, `value` is the option id. Show `recommended` as the text `(recommended)`.
- `multi`: checkbox, same name `value` repeated.
- `text`: `<input>` when size is `short`, `<textarea>` when `long`.
- `approve`: two submits, `value=approve` and `value=revise`. Revise requires the comment field (the server checks; the HTML `required` attribute is not enough).
- Every question also has `<input name="comment">`.
- Hidden `via=web`.

Follow-up form: one text field `text`, hidden `via=web`. Info entries with no `session_id` do not get this form.

POST handlers call `store.answer`, `store.add_followup`, `store.withdraw`, `store.archive`, or set `delivery.dismissed`. `ConflictError` renders the entry again with the error text, status 409. Success redirects to `/e/<id>`.

Escape every interpolated string with `html.escape`.

- [ ] **Step 4: SSE**

`GET /events` sets `Content-Type: text/event-stream` and `Cache-Control: no-cache`. It opens its own `db.connect()`, `LISTEN agent_inbox`, and writes `data: refresh\n\n` on each notify and also once immediately. It does not run `sweep`; slice 2's loop does that.

- [ ] **Step 2: Implement**

`GET /h/<id>` loads the entry and returns `html` wrapped as:

```html
<!doctype html>
<meta charset="utf-8">
<base target="_blank">
<p>diagram</p>
```

Headers:

```python
"Content-Security-Policy": "frame-ancestors http://127.0.0.1:8797 http://localhost:8797; sandbox allow-scripts allow-popups"
"X-Frame-Options": "ALLOWALL"  # do not set DENY; the CSP frame-ancestors is the control
```

Use the configured UI origin in `frame-ancestors` (`INBOX_UI_ORIGIN`, default `http://127.0.0.1:8797`). The frame server does not check the Tailscale header: the document is already only reachable on the tailnet because Tailscale is what publishes the port, and the UI iframe is the only intended client. Do not copy cookies onto this origin. There are no cookies.

Unknown id → 404.

- [ ] **Step 1: Start threads inside `run`**

Before the loop, start two daemon threads:

```python
def _serve_http() -> None:
    from agent_inbox.web import make_server
    make_server().serve_forever()

def _serve_frame() -> None:
    from agent_inbox.frame import make_server
    make_server().serve_forever()
```

`make_server()` binds `127.0.0.1` and the configured port.

- [ ] **Step 2: install.sh Tailscale**

After the inbox LaunchAgent bootstrap, if `command -v tailscale` succeeds:

```bash
tailscale serve --bg --yes --https=8444 http://127.0.0.1:8797
tailscale serve --bg --yes --https=8445 http://127.0.0.1:8798
```

If `tailscale` is missing, print `tailscale not on PATH; UI stays on 127.0.0.1` and continue. Do not fail the install.

The LaunchAgent environment must not include `INBOX_ALLOW_INSECURE`.
